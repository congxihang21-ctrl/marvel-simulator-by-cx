## 🎯 版本定位

Beta v2.2 是发给朋友测试的**私域内测版**；Beta v2.3 是**第一次在抖音公开公测**的版本。
本版本围绕以下三件事做了所有改动：

1. **把手机端小白玩家最容易踩的三个坑（P1/P2/P3）彻底填上**
2. **针对抖音 iOS WebView 容易清缓存丢存档的问题，做了多层存档容灾**
3. **文案全面改成"高三学生、课余独立开发"的真实身份，更贴合抖音年轻观众**

## 🛠 P 类 · 之前 N1/N2/N3 三建议的代码级修复

> 上一轮 v2.2 只是"加了样式/加了逻辑"，v2.3 把它们真正做到位、解决中间层不命中 / 死代码 / 误滚动的问题。

### ✅ P1 · 模态框底部栏 safe-area padding：子代选择器 → 后代选择器 + 扩展类名

**问题（v2.2 遗留）**：v2.2 用的是 `.modal .box > .ft, .modal .box > .actions` **子代选择器**（中间必须紧挨着）。实际 HTML 里按钮栏经常被一层 `<div class="row">` 或别的 wrapper 包一下，导致样式**完全命中不到**，iPhone Home Bar 依旧挡住"确定 / 关闭"按钮。

**修复内容**：
- 把所有子代选择器 `>` 改成 **后代选择器**（空格），允许中间有任意层包裹
- 一次性把所有项目实际用到的底部栏类名都列进去，防止漏网：
  `.ft / .actions / .footer / .modal-btns / .btn-row / .buttons / .modal-actions / .tut-btns / .modal-footer / .form-actions / .action-bar`
- padding-bottom 调整为 `calc(14px + env(safe-area-inset-bottom, 0px)) !important`，并加 `box-sizing: border-box !important` 避免撑高布局

**对应代码位置**：`2.3.html` 第 2446–2463 行（CSS）

**影响的端**：iOS（最严重）/ 鸿蒙 / 安卓全面屏机型 —— 现在所有模态框底部按钮都不会被系统手势条挡住。

---

### ✅ P2 · 自定义输入框 Enter/Done 提交：删除死代码 + 精简 chip 查找逻辑 + 复用 _cxChipPick

**问题（v2.2 遗留）**：`_cxInputEnter()` 函数里有三条小问题叠在一起：
1. 一开头 `var wrap=$('cx-chips')||null` —— **变量声明后从未用过**（死代码）
2. custom 分支用了**双重 for 循环**（先找 chipsContainers，再在每个容器里扫 spans），手风琴重渲容器时容易多份命中
3. preset 分支也写了一个大 for 循环去取消"留空"chip on 态，其实 DOM 里最多只有一个

**修复内容**：
- 整段死代码 `var wrap=$('cx-chips')||null` 直接删除
- custom 分支：改成 `document.querySelector('.cx-chips[data-fk="'+fk+'"] .cx-chip')` **一次查询定位容器**，循环节点只找第一个「自定义」chip 然后调用 `_cxChipPick(chip)`，和点击 chip 走完全同一条逻辑链
- preset 分支：改成 querySelector 直接定位"留空"chip 然后 `classList.remove('on')`，不再 for 循环
- 所有分支包进同一个 try，减少嵌套层级

**对应代码位置**：`2.3.html` 第 5980–6018 行（`function _cxInputEnter`）

**验证点**：iOS 键盘点「完成」、电脑端敲「回车」都能：自动选 chip / 取消「留空」选中 / 收起键盘，不会卡住。

---

### ✅ P3 · 简易模式剧情完自动滚选项卡：增加 45% 高度阈值，避免刚进游戏乱滚

**问题（v2.2 遗留）**：v2.2 的 `renderOpts` 每次渲染都调用 `scrollIntoView`，在刚切到游戏界面、剧情很短时也会猛滚一下，体验突兀。

**修复内容**：
- 仅当 `getMode() === 'easy'`（简易模式）才触发
- 增加高度阈值判断：`opts.getBoundingClientRect().top > window.innerHeight * 0.45`
  → **只有当选项确实在视口中下半段以下时才滚**，短剧情、刚切到游戏、专家模式都不打扰
- 继续用 `behavior: 'instant'`（不是 smooth），因为剧情完那一刻用户的手已经准备点选项了，不能等动画

**对应代码位置**：`2.3.html` 第 7682–7690 行（`renderOpts` 函数末尾）

**验证点**：剧情短 → 选项不动；剧情长滚到底 → 选项自动滚到视口顶部，正好出现在手指能点到的位置。

## 💾 D 类 · 存档容灾大升级（针对抖音 iOS WebView 易失特性）

> 抖音 iOS 版的内嵌 WebView 有个老毛病：**清后台、开太多页面、系统内存紧张时，localStorage 会被悄悄清空或半清空**。玩家玩了几百回合、追了好几个正典大事件，结果一夜归零 —— 这是抖音公开版最要命的风险。

### ✅ D-1：新增独立备份键 `cx_save_backup`

- 在 8585–8591 行声明新常量：`var CX_BACKUP_KEY='cx_save_backup'`
- 命名短、语义清晰（玩家甚至能在 DevTools / 浏览器数据管理里直接看到它），不像 `mcu_sim_state_v1_b1/b2/b3` 那样看一眼以为是缓存

### ✅ D-2：双写主 KEY + 独立备份键（三条路径全部双写）

1. `_rotateBackups(valStr)` 滚动备份链条里，**写完 B1/B2/B3 之后立即再写 `cx_save_backup`**
2. 节流 80ms 的 `save()` 在主落盘成功后，再**单独再写一次** `cx_save_backup`（二次保险，即使 `_rotateBackups` 抛错也不会掉链）
3. 切后台/关页/刷新前同步调用的 `_flushSaveSync()` 也同样**再写一次** `cx_save_backup`（iOS 切后台是最容易丢存档的时刻）

### ✅ D-3：恢复链条 `safeTryRestoreFromBackups()` 放 `cx_save_backup` 为**第一优先级**

- 新版 sources 顺序：`cx_save_backup (CxBack)` → 主 KEY → B1 → B2 → B3 → sessionStorage
- 原因：独立备份键**不参与滚动链条**（B1/B2/B3 会把旧值一层层往下推），清缓存时最容易被系统"放过"

### ✅ D-4：存档签名改 v2.3 + 温和提醒 banner

- `S._app='漫威模拟器 2.3'`（之前是 2.2，避免存档版本混乱）
- 保留每 15 回合 / 每天提醒一次的 banner：**「玩到 XX 回合 · 建议点💾存档→⬇导出TXT文件 存一份到自己相册/云盘」**，并加了「今天别再提醒 ✕」按钮，对小白足够友好也不骚扰。
